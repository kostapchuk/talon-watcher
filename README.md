# talon-watcher

Следит за записью к врачам на [talon.by](https://talon.by) и пишет в Telegram,
как только кнопка **«Записаться на платный приём»** становится кликабельной.

Пока умеет только платный приём. Бесплатные талоны — следующим шагом: у них
другая ссылка и другая разметка, поэтому у каждой слежки есть поле `kind`,
и проверялка берёт в работу только `paid`.

## Как это устроено

```
Cloudflare cron (раз в 5 минут)
        │  repository_dispatch
        ▼
GitHub Actions ── check.py ──► talon.by (страницы врачей)
        │                         │
        │  GET /watches           │  что на странице сейчас
        │  POST /notify ◄─────────┘  что изменилось
        ▼
Cloudflare Worker (бот) ──► Telegram
        │
        └── KV: подписчики, слежки и состояние каждой слежки
```

- **бот** (`bot/worker.js`, Cloudflare Workers) — общается с людьми и хранит
  всё: подписки, слежки и то, что мы в последний раз видели на странице;
- **проверялка** (`check.py`, GitHub Actions) — открывает страницы и говорит,
  что там сейчас. Между запусками не помнит ничего: слежки с их последним
  состоянием приезжают по `GET /watches`, случившиеся переходы уезжают
  обратно вместе с готовыми сообщениями по `POST /notify`;
- **расписание** — крон Cloudflare: он точный. Родной крон GitHub оставлен
  включённым как подстраховка, одновременные запуски встают в очередь.

Единственное, что обязано пережить запуск, — поле `available` на слежке,
то есть один бит «мы уже сказали, что открыто». Ради него отдельного
хранилища нет: он лежит там же, где сама слежка.

Зависимостей нет: проверялка — чистая стандартная библиотека Python, бот —
чистый Workers runtime.

## Команды бота

| Команда | Что делает |
|---|---|
| `/add <ссылка> [название]` | начать следить за врачом (можно просто прислать ссылку) |
| `/list` | слежки и их состояние прямо сейчас |
| `/remove` / `/remove_<id>` | перестать следить |
| `/check` | запустить проверку немедленно (не чаще раза в минуту) |
| `/start` / `/stop` | подписаться / отписаться (слежки при этом сохраняются) |

Больше трёх слежек на человека не даётся (`MAX_WATCHES` в `bot/worker.js`).

Ссылка нужна на карточку врача:
`https://talon.by/policlinic/klinika-merci/doctors/89829`. При добавлении бот
сам открывает страницу, проверяет, что врач существует, сразу говорит, что там
с записью, и записывает это состояние — поэтому ближайшая проверка не сообщит
об уже открытой записи как о новости.

## Что считается «появилась запись»

На странице врача кнопка бывает в трёх видах:

| Разметка | Смысл |
|---|---|
| `<a href="…/services/doctor/…" class="button">Записаться на платный приём</a>` | запись открыта → шлём уведомление со ссылкой |
| `<span class="button notAvailable">Записаться на платный приём</span>` | записи нет |
| кнопки нет вовсе | у врача нет платного приёма — бот предупреждает об этом при `/add` |

Открытие сообщается сразу. Закрытие — только после перепроверки: увидев, что
кнопка пропала у слежки, которая считалась открытой, проверялка через пять
секунд качает страницу заново. Выдача сайта иногда мигает, а без подтверждения
человек получил бы «закрылась» и следом «открылась».

## Развёртывание

### 1. Бот на Cloudflare

1. Создай бота у [@BotFather](https://t.me/BotFather), запомни токен.
2. Cloudflare → Workers & Pages → Create → подключи этот репозиторий.
   Сборка возьмёт `wrangler.toml`.
3. Storage & Databases → KV → создай namespace, его id впиши в `wrangler.toml`
   вместо `ЗАМЕНИ_НА_ID_KV_NAMESPACE` (привязка называется `SUBS`).
4. В `wrangler.toml` поправь `OWNER_CHAT_ID` и `GH_REPO` под себя.
5. Settings → Variables and Secrets, тип **Secret**:
   - `BOT_TOKEN` — токен от BotFather;
   - `WEBHOOK_SECRET` — любая длинная строка;
   - `BROADCAST_SECRET` — любая длинная строка, её же положишь в секреты GitHub;
   - `GH_TOKEN` — токен GitHub с правом `repo` (нужен для запуска проверки).
6. Открой `https://<воркер>.workers.dev/setup?key=<BROADCAST_SECRET>` — это
   привяжет вебхук и заведёт меню команд. Делается один раз.

Проверить настройку: `/health` покажет, какие переменные на месте и сколько
проверок подряд сайт не открывался, `/` — сколько подписчиков и слежек,
`/keys?values` — что лежит в KV.

### 2. Проверялка в GitHub

Settings → Secrets and variables → Actions:

- секреты: `BOT_URL` (`https://<воркер>.workers.dev`), `BROADCAST_SECRET`
  (та же строка, что у воркера);
- переменная (необязательно): `HEARTBEAT` — `edit` (по умолчанию), `every`
  или `off`. Даже при `off` проверялка отмечается у бота, просто молча.

Прав на запись в репозиторий воркфлоу не нужно — он ничего не коммитит.

Проверить связку: Actions → talon-watcher → Run workflow с галкой «ping» —
владельцу придёт тестовое сообщение.

**Держи репозиторий публичным.** Минуты Actions бесплатны только для публичных:
288 запусков в сутки с округлением каждого до минуты вылетают за бесплатные
2000 минут в месяц примерно вдвое.

**Про 60 дней.** GitHub отключает `schedule:`-крон после двух месяцев без
коммитов в репозиторий, а коммитить нам теперь нечего. Основное расписание
идёт от Cloudflare через `repository_dispatch` — его это правило не касается,
умрёт только резервный крон GitHub.

## Локальный запуск

```bash
cp .env.example .env      # заполнить
python3 check.py --once https://talon.by/policlinic/klinika-merci/doctors/89829
python3 check.py --watches          # что придёт из бота, вместе с состоянием
python3 check.py --dry-run -v       # полный обход, сообщения в консоль
```

Без `BOT_URL` проверялка работает автономно: берёт ссылки из `WATCH_URLS`
и шлёт напрямую в `TELEGRAM_CHAT_ID`. Состояние в этом режиме помнить негде,
так что она просто показывает, что на страницах сейчас.

| Ключ | Что делает |
|---|---|
| `--once URL` | посмотреть одну страницу и выйти |
| `--dry-run` | печатать сообщения вместо отправки |
| `--ping` | тестовое сообщение владельцу |
| `--watches` | показать слежки из бота |
| `--if-stale N` | работать, только если проверки не было N минут |

## Файлы

| Файл | Что это |
|---|---|
| `check.py` | обход страниц, поиск переходов, тексты сообщений |
| `bot/worker.js` | Telegram-бот, KV с подписками и состоянием, крон, запуск проверки |
| `wrangler.toml` | конфиг воркера: привязки, переменные, расписание |
| `.github/workflows/check.yml` | запуск проверялки раз в 5 минут |
